# Перевірки та умовні конструкції

Послідовне виконання команд — це одне, але щоб реалізувати будь-яку складнішу логіку у ваших скриптах або однорядкових командах (one-liners), вам знадобляться перевірки (tests) та умовні конструкції (conditionals). Перевірки визначають, чи є щось істинним (true), чи хибним (false). Умовні конструкції використовуються для прийняття рішень, які визначають хід виконання скрипта.

## Код завершення (Exit Status)

Кожна команда після свого завершення повертає код завершення (exit code). Цей код використовується програмою, яка її запустила, щоб оцінити, чи все пройшло успішно. Цей код завершення схожий на значення, що повертається з функцій. Це ціле число від 0 до 255 (включно). Загальноприйнята практика передбачає використання 0 для позначення успіху, а будь-якого іншого числа — для позначення певної помилки чи збою. Конкретне значення повністю залежить від самої програми і використовується як підказка щодо того, що саме пішло не так.

Наприклад, команда ping надсилає ICMP-пакети через мережу до певного хоста. Цей хост зазвичай реагує на такий пакет, відправляючи точнісінько такий самий у відповідь. Таким чином ми можемо перевірити, чи є у нас зв'язок із віддаленим хостом. Команда ping має низку кодів завершення, які можуть підказати нам, що пішло не так, якщо виникли якісь проблеми.

> Якщо ping взагалі не отримує жодних пакетів-відповідей, він завершує роботу з кодом 1. Якщо вказано як кількість пакетів, так і крайній термін (deadline), і до настання цього терміну отримано менше пакетів, ніж було задано, він також завершить роботу з кодом 1. У разі інших помилок він завершує роботу з кодом 2. В іншому випадку він завершує роботу з кодом 0. Це дає змогу використовувати код завершення, щоб дізнатися, чи доступний («живий») хост, чи ні.

Спеціальний параметр ? показує нам код завершення останнього процесу, що виконувався на передньому плані (foreground) і завершив свою роботу. Давайте трохи пограємося з командою ping, щоб подивитися на її коди завершення:

```bash
$ ping Good
ping: unknown host Good
$ echo $?
2
$ ping -c 1 -W 1 1.1.1.1
PING 1.1.1.1 (1.1.1.1) 56(84) bytes of data.
--- 1.1.1.1 ping statistics ---
1 packets transmitted, 0 received, 100% packet loss, time 0ms
$ echo $?
1
```

> Вам слід переконатися, що ваші скрипти завжди повертають ненульовий код завершення, якщо під час їхнього виконання сталося щось неочікуване. Ви можете зробити це за допомогою вбудованої команди exit:

```bash
 rm file || { echo 'Could not delete file!' >&2; exit 1; }
```

## Керуючі оператори (&& та ||)

Тепер, коли ми знаємо, що таке коди завершення і що код «0» означає успішне виконання команди, ми навчимося використовувати цю інформацію. Найпростіший спосіб виконати певну дію залежно від успіху попередньої команди — це використання керуючих операторів. Цими операторами є && та ||, які відповідно представляють логічне «І» (AND) та логічне «АБО» (OR). Ці оператори ставляться між двома командами й використовуються для керування тим, чи має виконуватися друга команда залежно від успіху першої. Ця концепція називається умовним виконанням.

Давайте застосуємо цю теорію на практиці:

```bash
$ mkdir d && cd d
```

Цей простий приклад складається з двох команд: `mkdir d` та `cd d`. Ви могли б використати крапку з комою (;) для розділення цих команд і їхнього послідовного виконання, але ми прагнемо більшого. У наведеному вище прикладі BASH виконає mkdir d, після чого оператор && перевірить результат роботи програми mkdir після її завершення. Якщо виконання mkdir було успішним (код завершення 0), то Bash виконає наступну команду — cd d. Якщо ж команда mkdir d зазнала невдачі й повернула ненульовий код завершення, Bash пропустить наступну команду, і ми залишимося в поточному каталозі.

Ось ще один приклад:

```bash
$ rm /etc/some_file.conf || echo "I couldn't remove the file"
rm: cannot remove `/etc/some_file.conf': No such file or directory
I couldn't remove the file
```

Оператор || дуже схожий на &&, але діє з точністю до навпаки. Він виконує наступну команду лише в тому випадку, якщо перша завершилася невдало. Таким чином, повідомлення буде виведено (через echo) лише тоді, коли команда rm не змогла виконати видалення.

Взагалі кажучи, не варто з'єднувати багато різних керуючих операторів в один довгий ланцюжок (ми дослідимо це в наступному розділі). Оператори && та || досить корисні в простих випадках, але не в складних сценаріях. У наступних кількох розділах ми покажемо інші інструменти, які можна використовувати для прийняття рішень.

> Найкраще не надто захоплюватися використанням операторів умовного виконання. Вони можуть зробити ваш скрипт важким для розуміння, особливо для людини, якій доручено підтримувати його і яка не є його автором.

## Групування операторів

Використання операторів умовного виконання — це простий і лаконічний спосіб, якщо нам потрібно зробити базову перевірку помилок. Проте все стає дещо небезпечнішим, коли ми хочемо виконати кілька операторів при дотриманні умови або коли нам потрібно оцінити кілька умов одночасно.

Припустимо, ви хочете видалити файл, якщо він містить певне «хороше» слово, але водночас не містить іншого — «поганого». Використовуючи grep (команду, яка перевіряє вхідні дані на відповідність шаблонам), ми можемо перекласти ці умови так:

```bash
grep -q goodword "$file"
! grep -q "badword" "$file"
```

Ми використовуємо прапор -q (quiet — «тихий» режим) для grep, тому що нам не потрібно виводити рядки, які відповідають шаблону; нам потрібно лише, щоб було встановлено відповідний код завершення.

Символ ! перед командою змушує Bash інвертувати (заперечувати) код завершення цієї команди. Якщо команда повертає 0 (успіх), ! перетворює його на помилку. І навпаки, якщо команда повертає ненульове значення (помилка), ! перетворює його на успіх.

Тепер, щоб об'єднати ці умови та видалити файл у разі, якщо обидві вони є істинними, ми могли б скористатися керуючими операторами:

```bash
$ grep -q goodword "$file" && ! grep -q badword "$file" && rm "$file"
```

Це працює чудово. (Насправді, ми можемо з’єднувати стільки &&, скільки забажаємо, без жодних проблем). Тепер уявіть, що ми хочемо вивести повідомлення про помилку в разі, якщо видалення файлу не вдалося:

```bash
$ grep -q goodword "$file" && ! grep -q badword "$file" && rm "$file" || echo "Couldn't delete: $file" >&2
```

На перший погляд, це виглядає нормально. Якщо код завершення rm не дорівнює 0 (успіх), тоді оператор || активує наступну команду і виведе повідомлення про помилку (>&2: у стандартний потік помилок).

Але є проблема. Коли ми маємо послідовність команд, розділених операторами умовного виконання, Bash розглядає кожну з них по черзі зліва направо. Код завершення «переноситься» від тієї команди, яка була виконана останньою, і пропуск команди його не змінює.

Отже, уявіть, що перший grep зазнає невдачі (встановлює код завершення 1). Bash бачить наступним &&, тому він взагалі пропускає другий grep. Потім він бачить ще один &&, тому він також пропускає rm, що йде за ним. Зрештою, він бачить оператор ||. Ага! Поточний код завершення — «помилка», і ми маємо ||, тому Bash виконує команду echo і повідомляє нам, що не зміг видалити файл — хоча він насправді навіть не намагався цього зробити! Це зовсім не те, чого ми прагнули.

Це не звучить занадто страшно, коли ви просто отримуєте неправильне повідомлення про помилку, але якщо не бути обережним, рано чи пізно це трапиться в більш небезпечному коді. Ви б не хотіли випадково видалити або перезаписати файли внаслідок помилки у вашій логіці!

Помилка в нашій логіці полягає в тому, що ми хочемо, щоб вирази rm та echo належали до однієї групи. echo пов'язаний із rm, а не з командами grep. Тож нам потрібно їх згрупувати. Групування здійснюється за допомогою фігурних дужок:

```bash
$ grep -q goodword "$file" && ! grep -q badword "$file" && { rm "$file" || echo "Couldn't delete: $file" >&2; }
```

(Примітка: не забувайте, що вам потрібна крапка з комою або розрив рядка перед закриваючою фігурною дужкою!)

Тепер ми згрупували команди rm та echo разом. Фактично це означає, що група розглядається як одна інструкція замість декількох. Повертаючись до нашої ситуації з невдалим першим grep: замість того, щоб Bash намагався виконати інструкцію && rm "$file", він тепер спробує виконати інструкцію && { ... }. Оскільки перед групою стоїть &&, а остання виконана команда завершилася невдало (той самий невдалий grep), Bash пропустить усю цю групу і рушить далі.

Групування команд можна використовувати не лише для операторів умовного виконання. Ми також можемо групувати їх для того, щоб перенаправити вхідні дані (input) одразу для цілої групи інструкцій замість однієї:

```bash
{
    read firstLine
    read secondLine
    while read otherLine; do
        something
    done
} < file
```

Тут ми перенаправляємо файл у групу команд, які зчитують вхідні дані. Файл буде відкрито під час запуску групи команд, він залишатиметься відкритим протягом усього часу її виконання і буде закритий після завершення роботи групи. Таким чином, ми можемо послідовно зчитувати рядки з нього за допомогою декількох команд.

```bash
cd "$appdir" || { echo "Please create the appdir and try again" >&2; exit 1; }
```
