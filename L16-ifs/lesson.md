## Умовні блоки (if, test та [[)

if — це ключове слово оболонки, яке виконує команду (або набір команд) і перевіряє код завершення цієї команди, щоб визначити, чи була вона успішною. Залежно від цього коду, if виконує певний блок команд.

```bash
$ if true
> then echo "Це була правда."
> else echo "Це була неправда."
> fi
Це була правда.
```

Тут ви бачите основну структуру оператора if. Ми починаємо з виклику if із командою true. true — це вбудована команда, яка завжди завершується успішно. if запускає цю команду, і як тільки вона завершується, перевіряє код виходу. Оскільки true завжди виходить успішно, if переходить до блоку then і виконує цей код. Якби команда true якимось чином зазнала невдачі та повернула код помилки, оператор if пропустив би код then і натомість виконав би блок else.

Різні люди мають різні вподобання щодо стилю написання операторів if. Ось кілька поширених варіантів:

```bash
if КОМАНДИ; then ІНШІ_КОМАНДИ; fi

if КОМАНДИ
then
    ІНШІ_КОМАНДИ
fi

if КОМАНДИ; then
    ІНШІ_КОМАНДИ
fi
```

Існують команди, створені спеціально для перевірки певних умов і повернення статусу виходу на основі знайденого. Перша така команда — test (також відома як [). Більш просунута версія називається [[. [ або test — це звичайна команда, яка зчитує свої аргументи та проводить з ними певні перевірки. [[ багато в чому схожа на [, але вона особлива (це ключове слово оболонки) і пропонує набагато більше можливостей. Перейдемо до практики:

```bash
$ if [ a = b ]
> then echo "a і b однакові."
> else echo "a і b не однакові."
> fi
a і b не однакові.
```

if виконує команду [ (пам'ятайте, вам не обов’язково потрібен if, щоб запустити команду [!) з аргументами a, =, b і ]. [ використовує ці аргументи, щоб визначити, що саме потрібно перевірити. У цьому випадку вона перевіряє, чи дорівнює рядок a (перший аргумент) рядку b (третій аргумент), і якщо це так, вона вийде успішно. Однак, оскільки рядок "a" не дорівнює рядку "b", [ не вийде успішно (код виходу буде 1). if бачить, що [ завершилася невдало, і виконує код у блоці else.

Останній аргумент, ], нічого не значить для [, але він обов’язковий. Спробуйте подивитися, що станеться, якщо його пропустити.

Ось приклад поширеної помилки при використанні [:

```bash
$ myname='Greg Wooledge' yourname='Someone Else'
$ [ $myname = $yourname ]
-bash: [: too many arguments
```

Здогадалися, у чому проблема?
Команда [ була виконана з аргументами Greg, Wooledge, =, Someone, Else та ]. Це 6 аргументів замість 4! [ не розуміє, який тест вона має виконати, оскільки очікує, що або перший, або другий аргумент буде оператором. У нашому випадку оператор став третім аргументом. Це ще одна причина, чому лапки надзвичайно важливі. Щоразу, коли ми вводимо пробіли в Bash, які мають належати до слова до або після них, нам потрібно брати їх у лапки. Це ж стосується і підстановки параметрів:

```bash
$ [ "$myname" = "$yourname" ]
```

Цього разу [ бачить оператор (=) у другому аргументі та може продовжувати свою роботу.

Щоб трохи полегшити нам життя, оболонка Korn представила (а Bash перейняв) новий стиль умовної перевірки під назвою [[. Він має кілька дуже цікавих функцій, яких немає у [.

Одна з особливостей [[ — це зіставлення за шаблоном (pattern matching):

```bash
$ [[ $filename = *.png ]] && echo "$filename схожий на файл PNG"
```

Інша функція [[ допомагає нам з підстановкою параметрів:

```bash
$ [[ $me = $you ]]           # Все добре.
$ [[ I am $me = I am $you ]] # Не працює!
-bash: conditional binary operator expected
-bash: syntax error near `am'
```

Цього разу змінні $me та $you не потребували лапок. Оскільки [[ — це не звичайна команда (як [), а ключове слово оболонки, вона має «магічні здібності». Вона аналізує свої аргументи до того, як вони будуть розгорнуті Bash, і сама виконує підстановку, сприймаючи результат як єдиний аргумент, навіть якщо він містить пробіли. (Іншими словами, [[ не дозволяє розділення слів (word-splitting) у своїх аргументах). Однак майте на увазі, що прості рядки все одно потрібно брати в лапки. [[ розглядає пробіл поза лапками як роздільник аргументів, як і зазвичай у Bash. Виправимо останній приклад:

```bash
$ [[ "I am $me" = "I am $you" ]]
```

Також є тонка різниця між використанням лапок і їх відсутністю з правого боку порівняння в [[. Оператор = за замовчуванням виконує зіставлення за шаблоном, якщо права частина не в лапках:

```bash
$ foo=[a-z]* name=lhunath
$ [[ $name = $foo   ]] && echo "Ім'я $name відповідає шаблону $foo"
Ім'я lhunath відповідає шаблону [a-z]*
$ [[ $name = "$foo" ]] || echo "Ім'я $name не дорівнює рядку $foo"
Ім'я lhunath не дорівнює рядку [a-z]*
```

Перший тест перевіряє, чи відповідає $name шаблону в $foo. Другий тест перевіряє, чи дорівнює $name тексту в $foo. Лапки справді мають значення — цю тонкість варто зауважити.

Пам’ятайте: використання лапок зазвичай дає саме ту поведінку, яку ви очікуєте, тому зробіть це звичкою. Опускайте їх лише тоді, коли ситуація вимагає саме нелапкованої поведінки. На жаль, помилки, спричинені неправильними лапками, часто важко знайти, тому що код часто залишається синтаксично правильним з лапками або без них, але може мати зовсім інше значення. У таких випадках bash не може сказати, що ви зробили щось не так; він просто робить те, що ви сказали, навіть якщо це не те, що ви планували.

Ви також можете об’єднати кілька операторів if в один, використовуючи elif замість else, де кожна перевірка вказує на іншу можливість:

```bash
$ name=lhunath
$ if [[ $name = "George" ]]
> then echo "Bonjour, $name"
> elif [[ $name = "Hans" ]]
> then echo "Goeie dag, $name"
> elif [[ $name = "Jack" ]]
> then echo "Good day, $name"
> else
> echo "Ти не George, Hans чи Jack. Хто ти такий, $name?"
> fi
```

Зверніть увагу, що < та > мають спеціальне значення в bash. Бліц-опитування: передбачте, що станеться, якщо ви виконаєте [ apple < banana ]. Перевірте свою гіпотезу (не підглядайте!). Грає музика з «Що? Де? Коли?»... Відповідь: bash шукатиме файл з назвою "banana" у поточному каталозі, щоб надіслати його вміст команді [ apple (через стандартний ввід). Припускаючи, що у вас немає файлу з назвою "banana", це призведе до помилки.

Бліц-опитування: припускаючи, що початковий намір команди — визначити, чи йде "apple" перед "banana" за алфавітом, як би ви змінили команду? Відповідь: екрануйте < зворотним слешем ось так: [ apple \< banana ] або використовуйте [[ замість [.

Зауважте, що оператори порівняння =, !=, > та < сприймають свої аргументи як рядки. Щоб операнди розглядалися як числа, потрібно використовувати інший набір операторів: -eq, -ne (не дорівнює), -lt (менше ніж), -gt, -le (менше або дорівнює) або -ge.

Бліц-опитування: придумайте приклад, який показує різницю між < та -lt. Оскільки "314" іде перед "9" лексикографічно (тобто в тому порядку, в якому їх розташував би словник), [ вважає, що перше є < ніж друге. Проте [ вважає, що "314" НЕ є -lt "9", бо триста чотирнадцять НЕ менше дев'яти.

Тепер, коли ви розумієте проблеми з лапками, розглянемо інші можливості, якими наділені [ та [[:

Тести, що підтримуються [ (test) та [[:

    -e ФАЙЛ: Істина, якщо файл існує.

    -f ФАЙЛ: Істина, якщо файл є звичайним файлом.

    -d ФАЙЛ: Істина, якщо файл є каталогом.

    -h ФАЙЛ: Істина, якщо файл є символічним посиланням.

    -p КАНАЛ: Істина, якщо іменований канал (pipe) існує.

    -r ФАЙЛ: Істина, якщо файл доступний вам для читання.

    -s ФАЙЛ: Істина, якщо файл існує і не порожній.

    -t FD: Істина, якщо файловий дескриптор FD відкритий у терміналі.

    -w ФАЙЛ: Істина, якщо файл доступний вам для запису.

    -x ФАЙЛ: Істина, якщо файл є виконуваним для вас.

    -O ФАЙЛ: Істина, якщо ви є власником файлу.

    -G ФАЙЛ: Істина, якщо файл належить вашій групі.

    ФАЙЛ1 -nt ФАЙЛ2: Істина, якщо перший файл новіший за другий.

    ФАЙЛ1 -ot ФАЙЛ2: Істина, якщо перший файл старіший за другий.

    -z РЯДОК: Істина, якщо рядок порожній (його довжина нуль).

    -n РЯДОК: Істина, якщо рядок не порожній.

Оператори рядків:

    РЯДОК1 = РЯДОК2: Істина, якщо рядки ідентичні.

    РЯДОК1 != РЯДОК2: Істина, якщо рядки не ідентичні.

    РЯДОК1 < РЯДОК2: Істина, якщо перший рядок іде раніше при сортуванні.

    РЯДОК1 > РЯДОК2: Істина, якщо перший рядок іде пізніше.

    ! ВИРАЗ: Інвертує результат виразу (логічне «НЕ»).

Числові оператори:

    ЦІЛЕ -eq ЦІЛЕ: Істина, якщо обидва цілих числа однакові.

    ЦІЛЕ -ne ЦІЛЕ: Істина, якщо числа не однакові.

    ЦІЛЕ -lt ЦІЛЕ: Істина, якщо перше число менше другого.

    ЦІЛЕ -gt ЦІЛЕ: Істина, якщо перше число більше другого.

    ЦІЛЕ -le ЦІЛЕ: Істина, якщо перше число менше або дорівнює другому.

    ЦІЛЕ -ge ЦІЛЕ: Істина, якщо перше число більше або дорівнює другому.

Додаткові тести, що підтримуються лише [[:

    РЯДОК = (або ==) ШАБЛОН: Не порівняння рядків, як у [, а зіставлення за шаблоном (glob).

    РЯДОК != ШАБЛОН: Істина, якщо рядок не відповідає шаблону.

    РЯДОК =~ РЕГУЛЯРНИЙ_ВИРАЗ: Істина, якщо рядок відповідає регулярному виразу.

    ( ВИРАЗ ): Дужки для зміни пріоритету обчислень.

    ВИРАЗ && ВИРАЗ: Логічне «ТА», але не обчислює другий вираз, якщо перший хибний.

    ВИРАЗ || ВИРАЗ: Логічне «АБО», але не обчислює другий вираз, якщо перший істинний.

Тести, ексклюзивні для [ (та test):

    ВИРАЗ -a ВИРАЗ: Істина, якщо обидва вирази істинні (логічне ТА).

    ВИРАЗ -o ВИРАЗ: Істина, якщо хоча б один вираз істинний (логічне АБО).

Приклади

```bash
$ test -e /etc/X11/xorg.conf && echo 'Ваш Xorg налаштовано!'
$ test -n "$HOME" && echo 'Ваш домашній каталог встановлено!'
$ [[ boar != bear ]] && echo "Вепрі — не ведмеді."
$ [[ boar != b?ar ]] && echo "Вепрі не схожі на ведмедів (за шаблоном)."
$ [[ $DISPLAY ]] && echo "Змінна DISPLAY не порожня, ймовірно, запущено Xorg."
$ [[ ! $DISPLAY ]] && echo "Змінна DISPLAY порожня, ймовірно, Xorg не запущено."
```

## Як групувати вирази в операторі `if` (наприклад, if (A AND B) OR C)?

Портативний спосіб (сумісний з POSIX або Bourne shell) полягає у використанні кількох команд `test` (або `[`):

```bash
# Bourne shell
if commandA && commandB || commandC; then
    ...
fi

# Або з викликами test(1):
if [ testA ] && [ testB ] || [ testC ]; then
    ...
fi
```

Коли оператори `&&` та `||` стоять між командами (на відміну від операторів всередині `[[...]]`), вони мають **однаковий пріоритет**, тому обробка йде зліва направо.

Якщо нам потрібне явне групування, можна скористатися фігурними дужками:

```bash
# Bourne shell
if commandA && { commandB || commandC; }; then
    ...
fi
```

> **Важливо:** Не варто намагатися використовувати оператори `-a` (AND) або `-o` (OR) всередині команди `test`, оскільки їхня поведінка офіційно не визначена стандартами й може призвести до помилок.

## Покращені методи (Bash, Zsh, ksh)

BASH, zsh та KornShell мають потужніші команди порівняння з простішими правилами використання лапок:

1.  **`((...))`**: для арифметичних виразів.
2.  **`[[...]]`**: для рядкових виразів та перевірки файлів.

### Приклади:

```bash
# Bash/ksh/zsh: Арифметичне групування
if (( (n > 0 && n < 10) || n == -1 )); then
    echo "0 < $n < 10 або n == -1"
fi
```

або

```bash
# Bash/ksh/zsh: Перевірка файлів та рядків
if [[ ( -f $localconfig && -f $globalconfig ) || -n $noconfig ]]; then
    echo "Конфігурація в нормі (або не використовується)"
fi
```

## Пріоритет операторів

Зверніть увагу, що на відміну від звичайних оболонок, оператор `&&` всередині `((...))` та `[[...]]` має **вищий пріоритет** за оператор `||` (так само як `-a` має пріоритет над `-o` у команді `[`).

Наприклад:
```bash
[ a = a ] || [ b = c ] && [ c = d ]
```
Цей вираз буде **хибним (false)**, тому що він обробляється зліва направо:
`{ [ a = a ] || [ b = c ]; } && [ c = d ]`

Тоді як:
```bash
[[ a = a || b = c && c = d ]]
```
Цей вираз буде **істинним (true)**, тому що `&&` має пріоритет:
`[[ a = a || ( b = c && c = d ) ]]`

## Важливість типу порівняння

Різниця між числовим та рядковим порівнянням є дуже суворою. Розглянемо приклад:

```bash
n=3
if [[ $n > 0 && $n < 10 ]]
then
    echo "$n знаходиться між 0 та 10"
else
    echo "ПОМИЛКА: некоректне число: $n"
fi
```

Результатом буде **"ПОМИЛКА: ..."**, оскільки при рядковому порівнянні `"3"` більше за `"10"`. Це відбувається тому, що символ `"3"` іде після `"1"`, а наступний символ `"0"` уже не береться до уваги.

Якщо замінити квадратні дужки `[[ ]]` на подвійні круглі `(( ))`, приклад працюватиме правильно, оскільки Bash почне порівнювати числа, а не символи.

## У чому різниця між `test`, `[` та `[[`?

Команда "відкрита квадратна дужка" `[` (вона ж команда `test`) та конструкція `[[ ... ]]` використовуються для обчислення виразів. 

*   **`[[ ... ]]`** працює лише в Korn shell (звідки вона походить), Bash, Zsh та нещодавніх версіях Yash і busybox. Вона є потужнішою.
*   **`[` та `test`** — це утиліти стандарту POSIX (зазвичай вбудовані в оболонку). POSIX не визначає конструкцію `[[ ... ]]`, хоча дозволяє оболонкам вважати `[[` зарезервованим словом.

### Приклади:

```bash
# POSIX (портативний варіант)
[ "$variable" ] || echo 'змінна не встановлена або порожня!' >&2
[ -f "$filename" ] || printf 'Файл не існує: %s\n' "$filename" >&2

# ksh, bash, zsh тощо
if [[ ! -e $file ]]; then
    echo "Файл не існує або недоступний." >&2
fi
```

Якщо коротко: `test` реалізує старий, портативний синтаксис. У майже всіх оболонках `[` є синонімом `test` (але вимагає `]` у кінці). Хоча сучасні оболонки мають вбудований `[`, зазвичай існує і зовнішній файл, наприклад `/bin/[`.

`[[` — це нова, покращена версія. Це не програма, а **ключове слово** оболонки. Це полегшує використання, оскільки оболонка обробляє вміст `[[ ... ]]` інакше, ніж аргументи звичайної команди.

### Порівняльна таблиця функцій

| Функція | Новий тест `[[` | Старий тест `[` | Приклад |
| :--- | :--- | :--- | :--- |
| **Рядкові оператори** | | | |
| Більше | `>` | `\>` (*) | `[[ a > b ]]` |
| Менше | `<` | `\<` (*) | `[[ az < za ]]` |
| Рівність | `= (або ==)` | `=` | `[[ a = a ]]` |
| Нерівність | `!=` | `!=` | `[[ a != b ]]` |
| **Цілі числа** | `-gt, -lt, -eq...` | `-gt, -lt, -eq...` | `[[ 5 -gt 10 ]]` |
| **Логіка** | | | |
| І (AND) | `&&` | `-a` (**) | `[[ -n $var && -f $var ]]` |
| АБО (OR) | `||` | `-o` (**) | `[[ -b $var || -c $var ]]` |
| Групування | `(...)` | `\( ... \)` (**) | `[[ $a = 1 && ($b = 2 || $c = 3) ]]` |
| **Маскування** | | | |
| Pattern matching | `=` (або `==`) | Немає | `[[ $name = a* ]]` |
| Регулярні вирази | `=~` | Немає | `[[ $date =~ ^Fri ]]` |

(\*) Оператори `<` та `>` стандартизовані лише в POSIX.1-2024, тому в старих `[` їх треба екранувати зворотним слешем.
(\*\*) У POSIX.1-2024 оператори `-a`, `-o` та групування `( )` всередині `[` більше не є частиною стандарту. Рекомендується використовувати кілька команд `[` замість них: `[ "$a" = a ] && [ "$b" = b ]`.

---

### Основні відмінності

1.  **Розбиття на слова (Word Splitting):**
    У `[[` змінна не розбивається на слова, навіть якщо в ній є пробіли, тому лапки часто не потрібні:
    ```bash
    file="назва файлу"
    [[ -f $file ]] # Працює!
    [ -f "$file" ] # У [ лапки обов'язкові
    ```
2.  **Групування:**
    У `[[` дужки не потрібно екранувати: `[[ -f $f1 && ( -d $d1 || -d $d2 ) ]]`.
3.  **Локаль:**
    Починаючи з Bash 4.1, `[[` враховує поточну локаль при порівнянні рядків (`<` або `>`), а `[` — ні.

---

### Теорія: Проста команда vs Складена команда

Різниця полягає в тому, що **`[` — це проста команда**, а **`[[` — складена команда**.
*   `[` отримує аргументи як будь-яка інша програма. Вона не може зупинити Bash від розкриття змінних або глобінгу (пошуку файлів за маскою) до того, як вони потраплять у команду.
*   `[[` створює спеціальний контекст парсингу. Вона може перевірити, чи порожній результат розширення, ще до того, як виникне помилка синтаксису.

**Порада:**
*   Використовуйте `[[` для рядків і файлів у Bash/Zsh/Ksh.
*   Використовуйте `(( ... ))` для чисел.
*   Використовуйте `[` лише якщо ваш скрипт має працювати на максимально старих або обмежених системах (POSIX/sh).

---

### Помилки при розборі (Parse-time errors)
Будь-яка помилка в операторі всередині `[[` призведе до того, що Bash завершить роботу скрипта ще на етапі розбору, навіть якщо ця частина коду ніколи не мала виконуватися. Якщо вам потрібна зворотна сумісність (наприклад, перевірка чи підтримує оболонка оператор `-v`), краще використовувати `[` або `eval`.

## Як визначити, чи містить змінна підрядок?

Тут є багато варіантів: ви можете виконати точний пошук підрядка, пошук за шаблоном у стилі "глоб" (glob-style) або пошук за допомогою регулярних виразів.

### 1. Точний збіг підрядка та шаблони (POSIX sh)
Для пошуку точних підрядків у стандартному `POSIX sh` використовується конструкція `case`:

```bash
# POSIX
case $bigvar in
    *substr*) ... ;;
esac
```

Якщо підрядок зберігається у змінній і вам потрібен точний збіг, назву цієї змінної слід взяти в лапки:

```bash
# POSIX
case $bigvar in
    *"$substr"*) ... ;;
esac
```

### 2. Використання [[ ... ]] (Bash)
У Bash ви також можете використовувати конструкцію `[[ ... ]]`. Вона підпорядковується тим самим правилам використання лапок, що й `case`:

```bash
# Bash
if [[ $bigvar = *substr* ]]; then ...    # Ці варіанти
if [[ $bigvar == *substr* ]]; then ...   # еквівалентні.

if [[ $bigvar = *"$substr"* ]]; then ...  # І ці також
if [[ $bigvar == *"$substr"* ]]; then ... # еквівалентні.
```

### 3. Пошук за шаблоном (Glob-style)
Як у `case`, так і в `[[ ... ]]` можна використовувати символи підстановки (globs). Просто пишіть символи маски без лапок. Якщо шаблон зберігається у змінній, не беріть її в лапки, і тоді вона буде інтерпретована як шаблон, а не як точний рядок.

```bash
# POSIX
case $filename in
    *.txt) ... ;;
esac

pattern='*.txt'
case $filename in
    $pattern) ... ;;
esac

# Bash
if [[ $filename = *.txt ]]; then ...
pattern='*.txt'
if [[ $filename == $pattern ]]; then ...
```
*Примітка: Починаючи з Bash 4.1, розширені оператори глобінгу (extglob) розпізнаються в `[[ ... ]]`, навіть якщо опція `extglob` не увімкнена явно.*

### 4. Регулярні вирази (Bash 3.x+)
У Bash версії 3.x і новіших `[[ ... ]]` підтримує розширені регулярні вирази (ERE) за допомогою оператора `=~`:

```bash
# Bash
# Збігається з "ac", "zabcz", "xabbbbcq" тощо.
re='ab*c'
if [[ $foo =~ $re ]]; then ...
```
**Наполегливо рекомендується** зберігати регулярний вираз у змінній і використовувати її без лапок (`=~ $variable`). Це допоможе уникнути багатьох небажаних сюрпризів із екрануванням символів.

### 5. Регулярні вирази в POSIX sh
У `POSIX sh` немає вбудованого оператора для регулярних виразів, але ви можете викликати стандартні утиліти, такі як `awk`, `expr` або `grep`:

```bash
# POSIX: Використання awk
ere_match() { awk -- 'BEGIN{exit !(ARGV[1] ~ ARGV[2])}' "$@"; }
if ere_match "$foo" "$re"; then ...

# Використання expr
# (expr за замовчуванням прив'язує вираз до початку рядка)
if expr "@$foo" : "@.*$re" > /dev/null; then ...

# Використання grep
# (Підходить лише для однорядкових рядків)
if printf '%s\n' "$foo" | grep -q -- "$re"; then ...
```

*   **`expr`** використовує базові регулярні вирази (BRE).
*   **`grep`** за замовчуванням використовує BRE, але з опцією `-E` підтримує розширені (ERE).
*   **`awk`** використовує варіант ERE, який також розпізнає деякі послідовності в стилі C (наприклад, `\n`).

Ось переклад вашого тексту про те, як перевірити, чи містить змінна коректне число.

## Як визначити, чи містить змінна коректне число?

Перш за все, потрібно визначити, що саме ви маєте на увазі під «числом». Найчастіше люди шукають «негативне ціле число без знака + попереду». Іншими словами — рядок, що складається лише з цифр. В інших випадках потрібно перевірити число з плаваючою крапкою, з можливим знаком (+/-) та десятковим розділювачем.

### Ручний розбір (Hand parsing)

Якщо вам потрібно перевірити просто «рядок цифр», це можна зробити за допомогою шаблону (glob):

```bash
# Bash / Ksh
if [[ -n $foo && $foo != *[!0123456789]* ]]; then
    printf '"%s" складається лише з цифр\n' "$foo"
else
    printf '"%s" містить не-цифру або порожній\n' "$foo"
fi >&2
```
*Порада: уникайте `[0-9]` або `[[:digit:]]`, оскільки в деяких локалях та системах вони можуть відповідати символам, відмінним від 0123456789.*

Те саме можна зробити в POSIX-сумісних оболонках за допомогою `case`:

```bash
# POSIX
case $var in
    '')
        printf 'змінна порожня\n';;
    *[!0123456789]*)
        printf '%s містить не-цифру\n' "$var";;
    *)
        printf '%s складається лише з цифр\n' "$var";;
esac >&2
```

Якщо вам потрібно дозволити знак «мінус» попереду або перевірити число з плаваючою крапкою, звичайних шаблонів (globs) може бути замало. Проте можна спочатку відрізати знак, а потім порівнювати:

```bash
# POSIX
case ${var#[-+]} in   # видаляємо префіксний знак
    '')                printf 'порожньо\n';;
    .)                 printf 'просто крапка\n';;
    *.*.*)             printf 'більше однієї крапки\n';;
    *[!0123456789.]*)  printf 'містить не-цифру\n';;
    *)                 printf 'схоже на число з плаваючою крапкою\n';;
esac >&2
```

У Bash можна використовувати **розширені шаблони** (extended globs):

```bash
# Bash (у версіях до 4.1 потрібно увімкнути shopt -s extglob)
shopt -s extglob
if [[ $var = +([0123456789]) ]]; then
    echo "це ціле число"
fi
```

### Регулярні вирази

Якщо ваше визначення «числа» складніше, або потрібне рішення для застарілих Bourne shell, краще використати регулярні вирази через `awk`:

```bash
# Bourne shell + awk
if awk -- 'BEGIN {exit !(ARGV[1] ~ /^[-+]?([0123456789]+\.?|[0123456789]*\.[0123456789]+)$/)}' "$foo"; then
    printf '"%s" є числом\n' "$foo"
else
    printf '"%s" не є числом\n' "$foo"
fi
```

Bash версії 3 і вище підтримує регулярні вирази безпосередньо в `[[...]]`:

```bash
# Bash
regexp='^[-+]?[0123456789]*(\.[0123456789]*)?$'
if [[ $foo = *[0123456789]* && $foo =~ $regexp ]]; then
    printf '"%s" схоже на число\n' "$foo"
fi
```

### Використання [ та printf (метод "-eq")

Існує «хитрий» спосіб перевірки цілих чисел через оператор порівняння:

```bash
# НЕ ПРАЦЮЄ В ksh
if [ "$foo" -eq "$foo" ] 2>/dev/null; then
    printf '"%s" є цілим числом\n' "$foo"
fi
```
Оператор `-eq` намагається розібрати аргумент як ціле число. Якщо розбір вдається — перевірка істинна, якщо ні — виникає помилка, яку ми приховуємо. **Увага:** цей метод небезпечний у `ksh`, оскільки він обчислює змінну як арифметичний вираз (що дозволяє ін'єкцію довільних команд).

Також будьте обережні з використанням `printf %f "$foo"`. Цей метод вважається **зіпсованим (broken)**, оскільки згідно з POSIX, якщо рядок починається з одинарної або подвійної лапки, `printf` поверне числовий код наступного за лапкою символу. Тобто рядок `'abc` буде помилково валідований як «число».

### Підсумок
Для надійності та безпеки (особливо в Bash) найкраще використовувати **ручний розбір через `case`** або **регулярні вирази**, де ви чітко вказуєте набір дозволених цифр `0123456789`.
