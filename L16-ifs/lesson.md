## Умовні блоки (if, test та [[)

if — це ключове слово оболонки, яке виконує команду (або набір команд) і перевіряє код завершення цієї команди, щоб визначити, чи була вона успішною. Залежно від цього коду, if виконує певний блок команд.

```bash
$ if true
> then echo "Це була правда."
> else echo "Це була неправда."
> fi
Це була правда.
```

Тут ви бачите основну структуру оператора if. Ми починаємо з виклику if із командою true. true — це вбудована команда, яка завжди завершується успішно. if запускає цю команду, і як тільки вона завершується, перевіряє код виходу. Оскільки true завжди виходить успішно, if переходить до блоку then і виконує цей код. Якби команда true якимось чином зазнала невдачі та повернула код помилки, оператор if пропустив би код then і натомість виконав би блок else.

Різні люди мають різні вподобання щодо стилю написання операторів if. Ось кілька поширених варіантів:

```bash
if КОМАНДИ; then ІНШІ_КОМАНДИ; fi

if КОМАНДИ
then
    ІНШІ_КОМАНДИ
fi

if КОМАНДИ; then
    ІНШІ_КОМАНДИ
fi
```

Існують команди, створені спеціально для перевірки певних умов і повернення статусу виходу на основі знайденого. Перша така команда — test (також відома як [). Більш просунута версія називається [[. [ або test — це звичайна команда, яка зчитує свої аргументи та проводить з ними певні перевірки. [[ багато в чому схожа на [, але вона особлива (це ключове слово оболонки) і пропонує набагато більше можливостей. Перейдемо до практики:

```bash
$ if [ a = b ]
> then echo "a і b однакові."
> else echo "a і b не однакові."
> fi
a і b не однакові.
```

if виконує команду [ (пам'ятайте, вам не обов’язково потрібен if, щоб запустити команду [!) з аргументами a, =, b і ]. [ використовує ці аргументи, щоб визначити, що саме потрібно перевірити. У цьому випадку вона перевіряє, чи дорівнює рядок a (перший аргумент) рядку b (третій аргумент), і якщо це так, вона вийде успішно. Однак, оскільки рядок "a" не дорівнює рядку "b", [ не вийде успішно (код виходу буде 1). if бачить, що [ завершилася невдало, і виконує код у блоці else.

Останній аргумент, ], нічого не значить для [, але він обов’язковий. Спробуйте подивитися, що станеться, якщо його пропустити.

Ось приклад поширеної помилки при використанні [:

```bash
$ myname='Greg Wooledge' yourname='Someone Else'
$ [ $myname = $yourname ]
-bash: [: too many arguments
```

Здогадалися, у чому проблема?
Команда [ була виконана з аргументами Greg, Wooledge, =, Someone, Else та ]. Це 6 аргументів замість 4! [ не розуміє, який тест вона має виконати, оскільки очікує, що або перший, або другий аргумент буде оператором. У нашому випадку оператор став третім аргументом. Це ще одна причина, чому лапки надзвичайно важливі. Щоразу, коли ми вводимо пробіли в Bash, які мають належати до слова до або після них, нам потрібно брати їх у лапки. Це ж стосується і підстановки параметрів:

```bash
$ [ "$myname" = "$yourname" ]
```

Цього разу [ бачить оператор (=) у другому аргументі та може продовжувати свою роботу.

Щоб трохи полегшити нам життя, оболонка Korn представила (а Bash перейняв) новий стиль умовної перевірки під назвою [[. Він має кілька дуже цікавих функцій, яких немає у [.

Одна з особливостей [[ — це зіставлення за шаблоном (pattern matching):

```bash
$ [[ $filename = *.png ]] && echo "$filename схожий на файл PNG"
```

Інша функція [[ допомагає нам з підстановкою параметрів:

```bash
$ [[ $me = $you ]]           # Все добре.
$ [[ I am $me = I am $you ]] # Не працює!
-bash: conditional binary operator expected
-bash: syntax error near `am'
```

Цього разу змінні $me та $you не потребували лапок. Оскільки [[ — це не звичайна команда (як [), а ключове слово оболонки, вона має «магічні здібності». Вона аналізує свої аргументи до того, як вони будуть розгорнуті Bash, і сама виконує підстановку, сприймаючи результат як єдиний аргумент, навіть якщо він містить пробіли. (Іншими словами, [[ не дозволяє розділення слів (word-splitting) у своїх аргументах). Однак майте на увазі, що прості рядки все одно потрібно брати в лапки. [[ розглядає пробіл поза лапками як роздільник аргументів, як і зазвичай у Bash. Виправимо останній приклад:

```bash
$ [[ "I am $me" = "I am $you" ]]
```

Також є тонка різниця між використанням лапок і їх відсутністю з правого боку порівняння в [[. Оператор = за замовчуванням виконує зіставлення за шаблоном, якщо права частина не в лапках:

```bash
$ foo=[a-z]* name=lhunath
$ [[ $name = $foo   ]] && echo "Ім'я $name відповідає шаблону $foo"
Ім'я lhunath відповідає шаблону [a-z]*
$ [[ $name = "$foo" ]] || echo "Ім'я $name не дорівнює рядку $foo"
Ім'я lhunath не дорівнює рядку [a-z]*
```

Перший тест перевіряє, чи відповідає $name шаблону в $foo. Другий тест перевіряє, чи дорівнює $name тексту в $foo. Лапки справді мають значення — цю тонкість варто зауважити.

Пам’ятайте: використання лапок зазвичай дає саме ту поведінку, яку ви очікуєте, тому зробіть це звичкою. Опускайте їх лише тоді, коли ситуація вимагає саме нелапкованої поведінки. На жаль, помилки, спричинені неправильними лапками, часто важко знайти, тому що код часто залишається синтаксично правильним з лапками або без них, але може мати зовсім інше значення. У таких випадках bash не може сказати, що ви зробили щось не так; він просто робить те, що ви сказали, навіть якщо це не те, що ви планували.

Ви також можете об’єднати кілька операторів if в один, використовуючи elif замість else, де кожна перевірка вказує на іншу можливість:

```bash
$ name=lhunath
$ if [[ $name = "George" ]]
> then echo "Bonjour, $name"
> elif [[ $name = "Hans" ]]
> then echo "Goeie dag, $name"
> elif [[ $name = "Jack" ]]
> then echo "Good day, $name"
> else
> echo "Ти не George, Hans чи Jack. Хто ти такий, $name?"
> fi
```

Зверніть увагу, що < та > мають спеціальне значення в bash. Бліц-опитування: передбачте, що станеться, якщо ви виконаєте [ apple < banana ]. Перевірте свою гіпотезу (не підглядайте!). Грає музика з «Що? Де? Коли?»... Відповідь: bash шукатиме файл з назвою "banana" у поточному каталозі, щоб надіслати його вміст команді [ apple (через стандартний ввід). Припускаючи, що у вас немає файлу з назвою "banana", це призведе до помилки.

Бліц-опитування: припускаючи, що початковий намір команди — визначити, чи йде "apple" перед "banana" за алфавітом, як би ви змінили команду? Відповідь: екрануйте < зворотним слешем ось так: [ apple \< banana ] або використовуйте [[ замість [.

Зауважте, що оператори порівняння =, !=, > та < сприймають свої аргументи як рядки. Щоб операнди розглядалися як числа, потрібно використовувати інший набір операторів: -eq, -ne (не дорівнює), -lt (менше ніж), -gt, -le (менше або дорівнює) або -ge.

Бліц-опитування: придумайте приклад, який показує різницю між < та -lt. Оскільки "314" іде перед "9" лексикографічно (тобто в тому порядку, в якому їх розташував би словник), [ вважає, що перше є < ніж друге. Проте [ вважає, що "314" НЕ є -lt "9", бо триста чотирнадцять НЕ менше дев'яти.

Тепер, коли ви розумієте проблеми з лапками, розглянемо інші можливості, якими наділені [ та [[:

Тести, що підтримуються [ (test) та [[:

    -e ФАЙЛ: Істина, якщо файл існує.

    -f ФАЙЛ: Істина, якщо файл є звичайним файлом.

    -d ФАЙЛ: Істина, якщо файл є каталогом.

    -h ФАЙЛ: Істина, якщо файл є символічним посиланням.

    -p КАНАЛ: Істина, якщо іменований канал (pipe) існує.

    -r ФАЙЛ: Істина, якщо файл доступний вам для читання.

    -s ФАЙЛ: Істина, якщо файл існує і не порожній.

    -t FD: Істина, якщо файловий дескриптор FD відкритий у терміналі.

    -w ФАЙЛ: Істина, якщо файл доступний вам для запису.

    -x ФАЙЛ: Істина, якщо файл є виконуваним для вас.

    -O ФАЙЛ: Істина, якщо ви є власником файлу.

    -G ФАЙЛ: Істина, якщо файл належить вашій групі.

    ФАЙЛ1 -nt ФАЙЛ2: Істина, якщо перший файл новіший за другий.

    ФАЙЛ1 -ot ФАЙЛ2: Істина, якщо перший файл старіший за другий.

    -z РЯДОК: Істина, якщо рядок порожній (його довжина нуль).

    -n РЯДОК: Істина, якщо рядок не порожній.

Оператори рядків:

    РЯДОК1 = РЯДОК2: Істина, якщо рядки ідентичні.

    РЯДОК1 != РЯДОК2: Істина, якщо рядки не ідентичні.

    РЯДОК1 < РЯДОК2: Істина, якщо перший рядок іде раніше при сортуванні.

    РЯДОК1 > РЯДОК2: Істина, якщо перший рядок іде пізніше.

    ! ВИРАЗ: Інвертує результат виразу (логічне «НЕ»).

Числові оператори:

    ЦІЛЕ -eq ЦІЛЕ: Істина, якщо обидва цілих числа однакові.

    ЦІЛЕ -ne ЦІЛЕ: Істина, якщо числа не однакові.

    ЦІЛЕ -lt ЦІЛЕ: Істина, якщо перше число менше другого.

    ЦІЛЕ -gt ЦІЛЕ: Істина, якщо перше число більше другого.

    ЦІЛЕ -le ЦІЛЕ: Істина, якщо перше число менше або дорівнює другому.

    ЦІЛЕ -ge ЦІЛЕ: Істина, якщо перше число більше або дорівнює другому.

Додаткові тести, що підтримуються лише [[:

    РЯДОК = (або ==) ШАБЛОН: Не порівняння рядків, як у [, а зіставлення за шаблоном (glob).

    РЯДОК != ШАБЛОН: Істина, якщо рядок не відповідає шаблону.

    РЯДОК =~ РЕГУЛЯРНИЙ_ВИРАЗ: Істина, якщо рядок відповідає регулярному виразу.

    ( ВИРАЗ ): Дужки для зміни пріоритету обчислень.

    ВИРАЗ && ВИРАЗ: Логічне «ТА», але не обчислює другий вираз, якщо перший хибний.

    ВИРАЗ || ВИРАЗ: Логічне «АБО», але не обчислює другий вираз, якщо перший істинний.

Тести, ексклюзивні для [ (та test):

    ВИРАЗ -a ВИРАЗ: Істина, якщо обидва вирази істинні (логічне ТА).

    ВИРАЗ -o ВИРАЗ: Істина, якщо хоча б один вираз істинний (логічне АБО).

Приклади

```bash
$ test -e /etc/X11/xorg.conf && echo 'Ваш Xorg налаштовано!'
$ test -n "$HOME" && echo 'Ваш домашній каталог встановлено!'
$ [[ boar != bear ]] && echo "Вепрі — не ведмеді."
$ [[ boar != b?ar ]] && echo "Вепрі не схожі на ведмедів (за шаблоном)."
$ [[ $DISPLAY ]] && echo "Змінна DISPLAY не порожня, ймовірно, запущено Xorg."
$ [[ ! $DISPLAY ]] && echo "Змінна DISPLAY порожня, ймовірно, Xorg не запущено."
```
